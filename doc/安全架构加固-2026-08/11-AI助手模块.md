# 11 AI 助手模块（horizonhub-ai）

> 第二阶段第二步。实现一个悬浮 AI 客服：右下角气泡按钮，点击进入对话，基于论坛数据回答问题、帮用户找帖子。
>
> 技术选型：**Spring AI 1.0.9 + OpenAI 兼容端点（可接 DeepSeek/通义/Kimi）+ 检索增强（RAG 思路）+ SSE 流式**。

## 涉及提交

- `feat: 新增 horizonhub-ai 模块骨架与 Spring AI 配置`
- `feat: 实现 AI 对话（检索增强 + SSE 流式）与论坛上下文检索`
- `feat: 前端悬浮 AI 助手组件（流式对话、登录检测）`

## 关键设计决策

### 1. AI 不直接查库，走「检索增强」

首版只读问答（非 Function Calling）。每次对话前，`ForumContextService` 预取论坛数据（板块树 + 热门/相关帖）拼进 prompt，让 LLM **基于真实数据回答**，避免幻觉：
- `buildSystemPrompt()`：角色设定（论坛助手「小H」）+ 全部板块结构。
- `buildUserContext()`：从用户提问粗提取关键词，有关键词则 `titleFuzzy` 搜相关帖、否则取热榜帖（各限 8 条，控制 token）。

### 2. 流式用 SseEmitter（WebMVC 项目）

本项目是 `spring-boot-starter-web`（非 WebFlux）。`ChatModel.stream()` 返回 reactor 的 `Flux<ChatResponse>`，在 WebMVC 下用 `SseEmitter` 手动订阅最稳妥：
```java
chatModel.stream(prompt)
    .map(ChatResponse::getResult)
    .map(g -> g.getOutput())
    .map(m -> m.getText())
    .subscribe(
        chunk -> emitter.send(SseEmitter.event().data(chunk)),
        emitter::completeWithError,
        emitter::complete
    );
```
取文本链路（Spring AI 1.0）：`response.getResult().getOutput().getText()`。

> **reactor 类型来源**：`horizonhub-ai` 显式引入 `spring-boot-starter-webflux` 仅作 Reactor 类型库（提供 Flux/Mono），**不改变 WebMVC 行为**——因 web 模块的 `spring-boot-starter-web` 在场，Spring Boot 仍用 Servlet 容器。

### 3. horizonhub-ai 作为 library 模块

不是独立服务，而是被打包进 web 应用的 library：web 的 pom 依赖 ai，ai 的端点（`/ai/*`）随 web 启动加载，复用 common 的 service/拦截器/Token。这样 AI 端点和论坛接口在同一进程，直接注入 `ForumArticleService`。

### 4. 登录态：不强制 + 个性化

AI 端点不标 `@GlobalInterceptor(checkLogin=true)`，**游客也能用**；通过 `BaseController.getUserInfoFromSession`（已兼容 Token/Session 双轨）取用户，登录则在提问前缀加昵称做个性化。前端检测 `userInfo` 显示「登录体验更佳」引导。

## 如何使用

### 启用 AI（关键：需注入 API key）
1. 申请 OpenAI 兼容服务 key（如 [DeepSeek](https://platform.deepseek.com)）。
2. 本地：在 web 的 `application-local.yml`（已被 .gitignore）写：
   ```yaml
   spring.ai.openai.api-key: sk-你的key
   ```
   或环境变量 `AI_API_KEY=sk-...`。
3. 未注入 key 时，AI 接口返回「AI 助手未配置」提示，**不影响系统其余功能**。

### 验证流程
1. 前端任意页面右下角可见悬浮「H」按钮，点击展开对话面板。
2. 未登录显示「游客模式，登录体验更佳」；登录后正常对话。
3. 输入「有什么热门帖子」→ AI 流式逐字输出基于真实帖子的推荐。
4. F12 看 Network：`/api/ai/chat` 是 `text/event-stream`，逐 chunk 返回。

## 验证 / 注意事项

- **编译**：`mvn compile`（common+ai+web）通过。
- **token 消耗**：每次对话都带板块树 + 8 条帖子摘要，token 适中；后续可加缓存或按需检索。
- **超时**：SSE 设 120s（LLM 生成较慢）；前端 `EventSource` 在服务端 `complete()` 后会触发 `onerror`，组件已 `close()` 避免重连。
- **安全**：AI 端点已纳入 web 的拦截器链（参数校验切面生效）；回答仅基于预取数据，无直接 DB 写权限。

## 刻意延后（后续阶段）

- **Function Calling**：让 AI 主动调用「搜文章/查板块/查我的文章」等工具，能力更强但复杂度高。
- **AI 代理写操作**：代用户发帖/评论（需 `AI_AGENT` scope Token + 审计日志 + 配额，第一阶段已预留）。
- **AI_AGENT scope 签发**：当前 AI 端点走 Session；若要 AI 服务独立部署，用第二阶段第一步的 Token 体系签发 `AI_AGENT` token。
- **对话历史/多轮上下文**：当前每轮独立（带系统提示+即时检索）；多轮需存历史并拼进 prompt。
- **Markdown 富渲染**：当前前端用简易 md 渲染（加粗/列表/换行）；可换 `v-md-editor` 的预览或 markdown-it。
- **配额限频**：AI 端点暂未接入 `FrequencyLimitAspect`（它按 userId 频率限制，可后续加 `AI_CHAT` 类型）。
